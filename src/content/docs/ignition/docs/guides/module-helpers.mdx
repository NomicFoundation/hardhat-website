When several parts of a deployment follow the same pattern, such as "deploy a contract, then call a function on it", you don't need to repeat that code in every module. A module definition is a normal function, so you can move the repeated part into a helper function that takes the module builder `m` and creates the `Future`s for you.

There is one thing to watch out for: [`Future` IDs](/ignition/docs/guides/creating-modules#future-ids). Every `Future` in a module needs a unique ID. If your helper creates the same IDs on every call, you can only call it once per module.

## Getting to know our contract

Inside the `contracts` directory, create a file called `Token.sol`:

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity ^0.8.28;

// A minimal token, only for this example
contract Token {
  string public name;
  string public symbol;
  mapping(address => uint256) public balanceOf;

  constructor(string memory name_, string memory symbol_) {
    name = name_;
    symbol = symbol_;
  }

  function mint(address to, uint256 amount) external {
    balanceOf[to] += amount;
  }
}
```

We want to deploy two of these tokens in one module, and mint some of each to an account.

## Writing the helper

The helper takes the module builder as its first argument. Its type, `IgnitionModuleBuilder`, comes from `@nomicfoundation/ignition-core`, so install that package as a development dependency to import it:

<Install packages="@nomicfoundation/ignition-core" />

Then, inside the `ignition` directory, create a file called `helpers/token.ts`:

```ts
import type {
  AccountRuntimeValue,
  IgnitionModuleBuilder,
} from "@nomicfoundation/ignition-core";

/**
 * Deploys a `Token` and mints `amount` of it to `holder`.
 *
 * Every `Future` id includes the token symbol, so this helper can be
 * called once per symbol in the same module.
 */
export function deployToken(
  m: IgnitionModuleBuilder,
  name: string,
  symbol: string,
  holder: AccountRuntimeValue,
  amount: bigint,
) {
  const token = m.contract("Token", [name, symbol], { id: `Token_${symbol}` });

  m.call(token, "mint", [holder, amount], { id: `Token_${symbol}_mint` });

  return token;
}
```

The important part is the `id` option. Both IDs are built from an argument of the helper, so each call creates different IDs. The helper returns the `Future`s that the caller may need, here the `token`, so they can be returned from the module or passed to other `Future`s.

Now use the helper in a module. Create `ignition/modules/Tokens.ts`:

```ts
import { buildModule } from "@nomicfoundation/hardhat-ignition/modules";
import { deployToken } from "../helpers/token.js";

export default buildModule("TokensModule", (m) => {
  const holder = m.getAccount(0);

  const gold = deployToken(m, "Gold", "GLD", holder, 1_000n);
  const silver = deployToken(m, "Silver", "SLV", holder, 5_000n);

  return { gold, silver };
});
```

Deploy it:

<Run command="hardhat ignition deploy ignition/modules/Tokens.ts" />

Each call of the helper created its own `Future`s (output shortened):

```
Batch #1
  Executed TokensModule#Token_GLD
  Executed TokensModule#Token_SLV

Batch #2
  Executed TokensModule#Token_GLD_mint
  Executed TokensModule#Token_SLV_mint

[ TokensModule ] successfully deployed 🚀
```

## What goes wrong without unique IDs

Here is the same helper without the `id` options:

```ts
// Don't do this: the ids don't depend on the arguments
export function deployTokenWrong(
  m: IgnitionModuleBuilder,
  name: string,
  symbol: string,
  holder: AccountRuntimeValue,
  amount: bigint,
) {
  const token = m.contract("Token", [name, symbol]);

  m.call(token, "mint", [holder, amount]);

  return token;
}
```

Hardhat Ignition generates the ID of `m.contract("Token", ...)` from the module ID and the contract name, so the first call creates `TokensWrongModule#Token`. The second call tries to create the same ID, and the module fails validation before anything is deployed:

```
HardhatError: HHE10702: Module validation failed with reason: The autogenerated future id ("TokensWrongModule#Token") is already used. Please provide a unique id, as shown below:

m.contract(..., { id: "MyUniqueId"})
```

Setting a fixed `id` such as `{ id: "Token" }` doesn't help either. The helper could still only be called once per module. Build the ID from the arguments that make each call different.

:::tip
If one module can call the helper several times with the same main argument, add an optional argument such as `instanceName` and include it in the IDs, so callers can tell the calls apart.
:::

## Keeping IDs stable

Hardhat Ignition uses `Future` IDs to store deployment results and to resume or modify a deployment. Once you have deployed a module that uses a helper, avoid changing how the helper builds its IDs, because Hardhat Ignition matches the `Future`s of a module to its previous results by ID. See [Modifying an existing module](/ignition/docs/guides/modifications) for more on how changes to a deployed module are handled.

## Testing the module

You can deploy the module in a test, the same way as any other module:

```ts
import assert from "node:assert/strict";
import { describe, it } from "node:test";
import { network } from "hardhat";

import TokensModule from "../ignition/modules/Tokens.js";

describe("TokensModule", async () => {
  const { ignition, viem } = await network.create();
  const [deployer] = await viem.getWalletClients();

  it("deploys one token per helper call and mints to the holder", async () => {
    const { gold, silver } = await ignition.deploy(TokensModule);

    assert.equal(await gold.read.symbol(), "GLD");
    assert.equal(await silver.read.symbol(), "SLV");
    assert.equal(await gold.read.balanceOf([deployer.account.address]), 1_000n);
    assert.equal(
      await silver.read.balanceOf([deployer.account.address]),
      5_000n,
    );
  });
});
```
